# نظام إدارة طلبات الإعانات الطبية

نظام داخلي لإدارة طلبات الإعانات الطبية في **جمعية بادر للأجهزة الطبية** (منطقة مكة المكرمة)، بديلًا عن ملف Excel بشيت شهري.

## ما يحلّه النظام

| مشكلة الملف القديم | ما يفعله النظام |
|---|---|
| عشرات الصياغات لنفس القيمة (`عاطل` / `عاطل ` / `متقاعد` / `تقاعد`) | كل قيمة قابلة للتصنيف قائمة مرجعية. لا حقل نصي حر للمدينة أو الحالة أو مصدر الدخل أو الصنف. |
| لا عمود تاريخ، فلا قياس لزمن الإنجاز | `status_history` يسجّل كل انتقال بوقته وصاحبه، والخط الزمني يعرض كم مكث الطلب في كل مرحلة. |
| تكرار المستفيدين بين الأشهر بلا سجل موحّد | المستفيد سجل واحد بهويته الوطنية، وكل طلباته معلّقة به. |
| أعمدة سير العمل تُترك فارغة | آلة حالات صارمة: لا انتقال خارج المسارات، ولا رفض أو تأجيل بلا سبب مكتوب. |
| بنود الطلب نص طويل في خلية واحدة | كل صنف مطلوب **صف مستقل** في `request_items`، مربوط بالكتالوج والمخزون. |

## التقنيات

Next.js 15 (App Router) · TypeScript strict · PostgreSQL 17 عبر Prisma · Auth.js v5 بجلسات قاعدة بيانات · Zod · Tailwind CSS مع رموز GitHub Primer · TanStack Table · React Hook Form · Vitest · Playwright.

## ترحيل بيانات Excel

```bash
# 1. تجربة بلا كتابة — تُنتج التقارير فقط
npm run migrate:excel -- --file "جدول اعانات 2026.xlsx" --dry-run

# 2. شهر واحد للمراجعة
npm run migrate:excel -- --file "جدول اعانات 2026.xlsx" --sheet يناير

# 3. كل الشهور بعد الاطمئنان
npm run migrate:excel -- --file "جدول اعانات 2026.xlsx"
```

السكربت **قابل لإعادة التشغيل**: كل طلب مرحَّل يحمل `legacy_row_ref` بصيغة `يناير!42`، فإعادة التشغيل تتخطّى ما رُحِّل ولا تُنتج نسخًا مكرّرة.

يُنتج ثلاثة تقارير في `reports/`:

| الملف | المحتوى |
|---|---|
| `unmatched_items.csv` | البنود التي لم تُطابَق مع الكتالوج — للمراجعة البشرية |
| `rejected_rows.csv` | الصفوف المرفوضة وسببها (هوية غير صالحة، بلا بنود…) |
| `migration_report.json` | الملخص الكامل بالأرقام |

### نتيجة الترحيل الفعلي

| المؤشر | العدد |
|---|---|
| الشيتات | 9 (يناير → سبتمبر) |
| الطلبات المُنشأة | 1,321 |
| المستفيدون الجدد | 709 |
| **عمليات دمج لهويات مكررة** | **736** |
| البنود المُنشأة | 4,072 |
| منها مطابَقة مع الكتالوج | 3,621 (89%) |
| غير مطابَقة | 451 |
| صفوف مرفوضة | 55 |

**ملاحظة تستحق قرارًا إداريًا:** معظم الـ451 بندًا غير المطابَق ليست أخطاءً إملائية بل **أصنافًا حقيقية تصرفها الجمعية وليست في الكتالوج المحدَّد**: الحليب الطبي والمكملات الغذائية، القساطر البولية، أكياس المفاغرة، الكمامات، المشدات الطبية، الأحذية الطبية، أجهزة شفط المفرزات، الجبائر، الرافعات الطبية، نقالات الإسعاف. تُراجَع في `unmatched_items.csv` ويُقرَّر إضافتها للكتالوج.

كما رُفض 55 صفًا لهويات غير صالحة، أغلبها أرقام من 9 خانات أو تبدأ بـ4 (مقيمون بوثائق أخرى). النظام لا يخترع رقمًا، بل يسجّلها لتصحيحها يدويًا.

## قرارات تصميم تستحق الشرح

### الجلسات قاعديّة، لا رموز JWT

تعطيل موظف أو تغيير كلمة مروره يجب أن يقطع وصوله في الحال. رمز JWT موقَّع يظل صالحًا حتى ينتهي أجله، فلا يكفي.

Auth.js v5 يرفض `session.strategy: 'database'` عندما يكون Credentials هو المزوّد الوحيد. لذلك تُستبدل دالتا ترميز الرمز وفكّه في [`src/lib/auth.ts`](src/lib/auth.ts): محتوى الكوكي **معرّف مبهم** يقابله صف في جدول `sessions`، والدور والحالة يُقرآن من قاعدة البيانات في كل طلب. حذف صف الجلسة يُنهي الوصول فورًا، وهو ما يفعله تعطيل الحساب وتغيير كلمة المرور.

### التكرار تنبيه لا منع

عند إدخال هوية مسجّلة مسبقًا يظهر تنبيه برابط لملف المستفيد، ويقرّر الموظف: طلب جديد لنفس الشخص أم خطأ إدخال؟ المنع القاطع كان سيدفع الموظفين لاختراع هويات وهمية، وهو أسوأ من التكرار.

### التطبيع لا يمسّ الاسم المعروض

`full_name` يُحفظ كما كتبه صاحبه. التطبيع (إزالة التشكيل، وتوحيد الهمزات والتاء المربوطة) يقع على `name_normalized` وحده، وهو حقل داخلي للبحث. مع فهرس `gin_trgm_ops` يجد البحث عن «عائشة» السجلَّ المخزَّن «عايشه».

### «مستلزمات» لا تظهر في الواجهة

العمود القديم في Excel اسمه `مستلزمات`، والاسم المعتمد في النظام الجديد **`كفالة مريض`** (`PATIENT_CARE`). الاسم القديم يُستعمل لقراءة ملف الترحيل فقط.

### أمر الصرف يُطبع من المتصفح لا من مكتبة PDF

المواصفة اقترحت `@react-pdf/renderer` أو Puppeteer. كلاهما يكسر النص العربي: مكتبات PDF في JavaScript لا تصل الحروف العربية ولا تضبط اتجاهها. البديل المطبَّق صفحة طباعة مستقلة على `/disbursements/[id]/print` بأنماط `@media print` ومقاس A4، يحفظها الموظف PDF عبر «طباعة إلى PDF» في المتصفح. محرّك المتصفح يرسم العربية رسمًا صحيحًا، والمخرَج PDF حقيقي، وبلا اعتماد إضافي على الخادم. رمز التحقق QR يُولَّد على الخادم بمكتبة `qrcode` كـSVG مضمَّن.

### المخزون: الرصيد نتيجة لا رقم

لا يتغيّر رصيد في هذا النظام إلا ومعه صف في `stock_movements`. الحجز لا يخصم بل يرفع `quantity_reserved` فيقلّ **المتاح**، والخصم الفعلي يقع لحظة إصدار أمر الصرف داخل نفس معاملة تغيير الحالة — فإن لم يكف الرصيد لم يُصدَر أمر ولم تتغيّر الحالة. البند الذي لا يجده المستودع يتحوّل تلقائيًا إلى `to_purchase` فيظهر في لوحة المشتريات بلا خطوة يدوية بين القسمين.

### الإشعار يُكتب قبل أن يُرسل (Outbox)

الرسالة تُكتب في جدول `notifications` **داخل نفس معاملة تغيير الحالة**، ثم تُرسل بعد نجاحها. هذا الترتيب يحلّ مشكلتين معًا: لا تصل المستفيد رسالة عن تغيير حالة تراجعت معاملته، ولا تضيع رسالة لأن المزوّد كان متوقفًا — تبقى `queued` ويلتقطها العامل.

`BullMQ + Redis` مطبَّق في [scripts/worker.ts](scripts/worker.ts)، لكن **Redis ليس شرطًا للتشغيل**: مصدر الحقيقة هو الجدول لا الطابور، فحين لا يوجد `REDIS_URL` يعمل العامل بحلقة كل 30 ثانية، ويُشغَّل تفريغ فوري بعد كل تغيير حالة. غياب Redis يؤخّر الرسالة لا يفقدها.

المزوّد الافتراضي `log` يسجّل ولا يرسل، فلا تذهب رسالة حقيقية لرقم حقيقي أثناء التطوير. للتفعيل: `NOTIFICATIONS_DRIVER=whatsapp` مع `WHATSAPP_TOKEN` و`WHATSAPP_PHONE_ID`، أو `sms` مع `SMS_ENDPOINT` و`SMS_API_KEY`.

**الرسائل لا تذكر أي تفصيل صحي ولا اسم جهاز** — تصل هاتفًا قد يقرأه غير صاحبه. ولا تُرسل عن المراحل الداخلية (الفرز، المستودع، المشتريات): إغراق المستفيد برسائل لا تعنيه يدرّبه على تجاهلها.

### بوابة المستفيد: مصادقة برمز لمرة واحدة

الجمهور مجهول والواجهة عامة، فالضوابط أشدّ:

- **لا كشف عن وجود سجل.** رقم هوية غير مسجّل يتلقى نفس الرد الذي يتلقاه المسجّل.
- **الرمز مجزَّأ لا مخزَّن**، صالح خمس دقائق، وخمس محاولات ثم يُقفل، وثلاثة رموز لكل رقم في الساعة.
- **جلسة منفصلة تمامًا** عن جلسات الموظفين: كوكي مختلف وجدول `portal_sessions` مختلف ومدة ساعتين — ثغرة في البوابة لا تفتح النظام الداخلي.
- **لا تسجيل ذاتي.** من ليس مسجّلًا يراجع الجمعية؛ التسجيل الذاتي يفتح باب هويات وهمية.
- **طلبان مفتوحان كحد أقصى** لكل مستفيد عبر البوابة.
- **ما يراه المستفيد أقل بكثير مما يراه الموظف**: الحالة وتاريخها والأصناف — بلا ملاحظات داخلية ولا أسماء موظفين.

### مؤشرات الزمن تستثني السجلات المرحَّلة

ملف Excel القديم لم يكن فيه أي عمود تاريخ، فتواريخ السجلات المرحَّلة اصطناعية (أول الشهر). إدخالها في «متوسط زمن الإنجاز» و«متوسط زمن كل مرحلة» يعطي صفرًا كاذبًا، فهي مستثناة بشرط `legacyRowRef: null`. المؤشر يقيس ما تتبّعه النظام فعلًا.

## حماية البيانات

النظام يتعامل مع هويات وطنية وبيانات صحية، ويخضع لنظام حماية البيانات الشخصية السعودي:

- **لا حذف نهائي.** كل الجداول بحذف ناعم، و`audit_log` يسجّل القيم قبل وبعد كل تعديل.
- **إخفاء جزئي لرقم الهوية** (`1XXXXXX816`) لكل دور لا يملك `beneficiary:read_full_id`.
- **صلاحيات على مستوى الحقل**: البيانات الصحية التفصيلية محجوبة عن دور الاطّلاع.
- **تسجيل كل اطّلاع** على ملف مستفيد في `beneficiary_access_log` بصاحبه ووقته وعنوانه.
- **المرفقات لا تُخدَم من مسار عام**؛ تنزيلها يمرّ بتحقق من الجلسة والصلاحية.
- **الاستضافة داخل المملكة** شرط إنتاجي — راجع قسم النشر أدناه.

## ملاحظات تشغيلية

- **المشروع داخل مجلد Dropbox.** مجلدات `node_modules` و`.next` و`test-results` و`playwright-report` و`storage` مستثناة من المزامنة عبر سمة `com.dropbox.ignored`. بدون هذا الاستثناء يفشل البناء بأخطاء `EBUSY` و`EPERM` لأن Dropbox يقفل الملفات أثناء المزامنة. عند استنساخ المشروع على جهاز آخر داخل Dropbox، كرّر الاستثناء:

  ```powershell
  Set-Content -Path '.\node_modules:com.dropbox.ignored' -Value 1
  Set-Content -Path '.\.next:com.dropbox.ignored' -Value 1
  ```

- **التخزين المحلي للمرفقات** (`STORAGE_DRIVER=local`) للتطوير فقط. الإنتاج يحتاج تخزينًا متوافقًا مع S3 داخل المملكة.
